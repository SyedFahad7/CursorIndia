# Cursor + Notion Event Proposal (India)

**Prepared by:** Syed Fahad, Cursor Ambassador (India)
**Shared via:** Roshini (Cursor team)
**For:** Notion partnerships / community review

---

## Summary

This is a proposal for a joint Cursor and Notion community event in India. The goal is to show teams how planning in Notion and building in Cursor can work as one workflow, not two separate tools.

**One line pitch:** Plan in Notion. Ship in Cursor. Document in Notion.

---

## What is this event?

A hands on workshop where attendees learn how to connect Notion and Cursor in real workflows.

Most people already use Notion for docs, specs, and task boards. Many developers already use Cursor. What they have not seen is the full loop: plan in Notion, delegate work to a Cursor agent, ship a pull request, and document the result back in Notion.

This event teaches that loop live. Attendees leave having installed the Notion integration, run real prompts against a sample workspace, and seen an agent go from a Notion task to a working PR.

---

## Why Cursor + Notion together?

Notion holds the context. Cursor does the work.

Together they close a gap most teams still feel every day: copying specs into the IDE, manually updating task status after every PR, and losing decisions that live in docs while code lives in GitHub.

**What makes this different from a regular Cursor meetup:**

- Not a feature tour or a "build a React button" demo
- Shows the Notion to Cursor SDK flow: assign a task in Notion, watch the agent run, get a PR back on the task
- Shows Notion MCP inside Cursor: the agent reads your workspace while it codes
- Shows non developer use cases too: reports, meeting recaps, and research pulled from Notion context

This aligns with how both companies are positioning the partnership. Notion as the orchestration layer. Cursor as the execution engine.

## Event structure

**Format:** 90 minute flagship workshop (can also run as a 60 minute version or an expo station at a larger Cursor event)

**Suggested location:** Hyderabad or Bangalore (open to other cities)

**Capacity:** 80 to 150 attendees

### Run of show

| Block | Duration | What happens |
| --- | --- | --- |
| Welcome and story | 10 min | Why Notion + Cursor, the closed loop, who this is for |
| Demo 1: One click setup | 10 min | Install Notion MCP from the Cursor marketplace, connect workspace via OAuth |
| Demo 2: Agent reads your wiki | 15 min | Cursor searches Notion specs and task databases while working on code |
| Demo 3: Task board to PR | 20 min | Assign a bug from a Notion task database to Cursor, watch the agent stream progress, PR link appears on the task |
| Demo 4: Document the work | 10 min | After code ships, generate a Notion doc explaining what changed for the wider team |
| Hands on | 15 min | Attendees try 2 to 3 prompts on a shared demo workspace |
| Q&A and next steps | 10 min | How to keep using this at work, trial info, community links |

### What attendees need

- Laptop with Cursor installed
- A Notion account (Business plan needed for the SDK assignment flow; free plan works for MCP demos)
- GitHub account connected to Cursor (for PR demos)

### What we provide

- A pre built Notion demo workspace (spec pages, task database, sample bugs) that attendees can duplicate
- Step by step prompt cards for the hands on section
- Recording shared with all registered participants after the event

### Optional add ons

- **Dual track:** Engineering track (SDK + PR flow) and Knowledge Work track (reports, research, meeting prep from Notion context)
- **Expo station:** A 5 minute "Context Loop" challenge at a larger Cursor India roadshow
- **Online follow up:** A 45 minute Zoom session one week later for teams who want help setting this up at their company

## What we will show

1. **Your task board hired an engineer.** Assign a bug from a Notion task. Watch the Cursor agent plan, code, test, and open a PR. Every step visible on the task.

2. **The agent read your entire wiki.** Cursor pulls specs, architecture decisions, and past notes from Notion while working on code. No copy paste.

3. **Spec to shipped.** A PRD in Notion becomes an implementation plan, then code, then a PR. Status updates on the task automatically.

4. **Documentation that writes itself.** After a PR merges, Cursor generates a Notion doc explaining what changed for PMs and stakeholders.

5. **Works for non developers too.** Pull goals from Notion, combine with recent notes, draft a stakeholder update. No repository needed.
